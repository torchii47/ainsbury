Content Area 8: Security

Content area 8 covers what organisations need to protect, the threats and vulnerabilities they face, how to reduce the risk, and the models (CIA and IAAA) that tie security together. Exam questions usually give a scenario and ask you to identify a threat, explain its impact and recommend prevention. Always link the prevention to the specific threat.

Links to other content areas: data protection and the Computer Misuse Act are in Content area 4. Security breaches as a business risk are in Content area 5 (5.3). Device hardening, backups and patching also appear in Content area 7 (7.6).

Worked example: SQL injection

This login check builds the SQL query by joining strings. Entering ' OR '1'='1 as the password makes the condition always true, so the attacker logs in without knowing the password.

import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE users (name TEXT, password TEXT)")
db.execute("INSERT INTO users VALUES ('admin', 'S3cret!')")

name = "admin"
password = "' OR '1'='1"

# Vulnerable: user input joined straight into the SQL
query = ("SELECT * FROM users WHERE name = '" + name +
         "' AND password = '" + password + "'")
print("Vulnerable login:", db.execute(query).fetchone() is not None)

# Safe: parameterised query treats the input as data, not code
safe = "SELECT * FROM users WHERE name = ? AND password = ?"
result = db.execute(safe, (name, password)).fetchone()
print("Safe login:", result is not None)

Vulnerable login: True
Safe login: False

See the query the attacker builds

Worked example: salted hashing


import hashlib
import os

def hash_password(password, salt):
    return hashlib.sha256(salt + password.encode()).hexdigest()

salt = os.urandom(16)                  # random salt, stored with the hash
stored = hash_password("Summer2026!", salt)

print(len(stored))                                    # always 64 characters
print(hash_password("Summer2026!", salt) == stored)   # correct
print(hash_password("summer2026!", salt) == stored)   # one letter wrong



64
True
False


                        
The system never stores the password, only the salt and hash. At login it hashes what the user typed and compares. A random salt means two users with the same password get different hashes, which defeats pre-computed tables of common password hashes. (Real systems use slow hashing algorithms designed for passwords, such as bcrypt or Argon2.)

                        
Try it: SHA-256 in your browser

                        

                            
                            
                            
                        

                        

                        
Change one letter of the password and watch the whole hash change. Same password, new salt: a completely different hash.

8.3.2 Internet security processes

                    

                        
Firewall configuration

                        
A firewall checks traffic against rules and allows or blocks it.

                        

                            
Rule typeExample

                            
Rules for traffic: inbound and outboundBlock all inbound traffic except to the web server; block outbound traffic to known malicious sites.

                            
Traffic type rulesAllow HTTPS (port 443); block Telnet (port 23) and FTP.

                            
Application rulesAllow Teams; block peer-to-peer file sharing apps.

                            
IP address rulesAllow admin access only from the office IP range; block IP addresses from known attackers.

                        


                        
Network segregation

                        

                            
TypeMeaningExample

                            
VirtualOne physical network divided into separate logical networks (VLANs).Guest Wi-Fi kept separate from staff network; card payment systems on their own VLAN

                            
PhysicalCompletely separate hardware and cabling.Factory control systems on their own network

                            
Offline networkNot connected to the internet at all (air-gapped).Classified government systems; backup storage

                        

                        
Why: if one segment is compromised, the attacker can't easily reach the others; sensitive systems get stronger controls; traffic is easier to monitor.


                        
Network monitoring and port scanning

                        
    
                            
  • Network monitoring: tools watch traffic levels, devices and logs in real time. Unusual activity (a spike in traffic at 3am, logins from abroad, large uploads) is flagged so staff can respond before damage spreads.
    • 
                            
  • Port scanning: regularly scanning your own network finds open ports and services that should not be there, so they can be closed before an attacker finds them.
    • 
                        

                        

                            
Firewall
Hardware or software that controls network traffic in and out using rules.

                        

                    

                


                

                    
8.4 Components of effective security

                    

                        
The CIA triad (8.4.1)

                        

                            
ElementMeaningHow it is achievedExample of failure

                            
ConfidentialityData is kept private by controlling who has access to it.Encryption, access control, authenticationHacker reads customer records

                            
IntegrityData has not been tampered with and is accurate. Maintaining confidentiality helps protect integrity.Hashing, access control, validation, audit logs, backupsMalware changes prices in a database

                            
AvailabilityData and systems are available and useful when needed. Maintaining integrity helps ensure availability.Redundancy, backups, DDoS protection, patchingRansomware locks files; DDoS takes site offline

                        

                        
How they interrelate: if confidentiality fails (an attacker gets in), integrity is at risk (they can change data); if integrity fails (data is corrupted), the data is no longer useful, so in practice it is not available. Measures can also conflict: very strict access controls protect confidentiality but can reduce availability for genuine users.


                        
The IAAA model (8.4.2)

                        

                            
StagePurposeTechniquesBenefitsDrawbacks

                            
IdentificationRecognising the individual within a digital system: who do you claim to be?Knowledge-based (username, email); possession-based (ID card, key fob); biometric (fingerprint, face)Every user has a unique identityUsernames are often easy to guess or find

                            
AuthenticationVerifying the identity claimed during identification: prove it.Passwords and passphrases; multi-factor authentication; biometric authenticationMFA greatly reduces account takeover; biometrics can't be forgottenPasswords forgotten, reused or stolen; biometrics can't be changed if compromised and raise privacy concerns

                            
AuthorisationEnsuring authenticated users can only access resources and perform actions they are permitted to.Role-based access control (permissions by job role); access control listsLeast privilege limits damage; easy to manage by roleRoles must be kept up to date when people change jobs; complex in large organisations

                            
AccountabilityEnsuring any action can be traced back to the responsible user.Audit logs; monitoring user activityDeters misuse; evidence for investigations; meets regulationsLogs need storage and someone to review them; privacy concerns about monitoring

Describe the difference between a virus and a worm.

                                
  • A virus attaches to a file/program and needs the user to run or share it to spread (1); a worm self-replicates and spreads across networks without user action (1).

                            

                            

                                
Staff at an accountancy firm receive a text message claiming to be from HMRC with a link to claim a tax refund. (a) Identify this type of attack. (b) Explain two ways the firm could reduce the risk.

                                
  • (a) Smishing (1).
  • (b) Method (1) + explanation (1), twice. E.g. staff training (1) so staff recognise fake messages and don't click links (1); MFA on accounts (1) so stolen details alone can't be used (1); policy to verify by contacting HMRC through the official website/number (1) rather than the link (1).

                            

                            

                                
Explain how SQL injection works and one method to prevent it.

                                
  • Attacker enters SQL code into an input field (1)
  • which is joined into a query and executed by the database (1)
  • allowing data to be read, changed or deleted / login bypassed (1).
  • Prevention: parameterised queries / input validation and sanitisation / least-privilege database accounts (1).

                            

                            

                                
State three prevention methods for human threats, according to the type of threat.

                                
  • Any three from the spec, e.g. confirmation boxes / file properties / staff training (human error); immediate removal from premises / suspend user accounts (malicious employee); accompany visitors / check ID (disguised criminal); lock unattended machines / don't write down passwords / password management (poor cyber hygiene).

                            

                            

                                
Explain two physical security measures a data centre could use to prevent unauthorised access.

                                
  • Measure (1) + explanation (1), twice. E.g. entry control systems with key cards or biometrics (1) so only authorised staff can enter (1); prevent tailgating with turnstiles or mantraps (1) so one person enters per authorisation (1); CCTV monitoring (1) deters and records intruders (1); audit staff access (1) to spot unusual access patterns (1).

                            

                            

                                
Compare symmetric and asymmetric encryption.

                                
  • Symmetric uses the same key to encrypt and decrypt; asymmetric uses a public key to encrypt and a private key to decrypt (1)(1).
  • Symmetric is faster / suited to large data (1); asymmetric avoids the problem of sharing a secret key securely / supports digital signatures (1).

                            

                            

                                
A company makes a full backup every Sunday and an incremental backup every other day. Its server fails on Thursday. State which backups are needed to restore the data and explain why.

                                
  • Sunday's full backup (1)
  • plus Monday, Tuesday and Wednesday incremental backups (1)
  • because each incremental only contains changes since the previous backup, so all are needed in order (1).

                            

                            

                                
Explain why passwords should be stored as salted hashes rather than encrypted.

                                
  • Hashing is one-way so the original password cannot be recovered even if the database is stolen (1); encryption can be reversed if the key is stolen (1).
  • A salt makes identical passwords produce different hashes / defeats pre-computed tables of common password hashes (1).

                            

                            

                                
Describe two types of firewall rule.

                                
  • Rule type (1) + description/example (1), twice: inbound/outbound traffic rules; traffic type (port/protocol) rules; application rules; IP address rules.

                            

                            

                                
Explain how the elements of the CIA triad interrelate, using an example.

                                
  • Confidentiality: data private by controlling access (1); integrity: data not tampered with (1); availability: data accessible and useful (1).
  • Linked example (1): e.g. if an attacker gains access (confidentiality lost) they could alter records (integrity lost) so the records can no longer be relied on (availability effectively lost).

                            

                            

                                
An online retailer's customers log in to view orders. Explain how each stage of the IAAA model applies to this system.

                                
  • Two marks per stage: one for describing the stage, one for applying it to the retailer.
  • Identification: customer enters their email/username (1) which the system recognises as a customer account (1).
  • Authentication: password plus MFA code sent to their phone / app (1) verifies the customer is who they claim (1).
  • Authorisation: customer can only view their own orders, not others' / staff roles differ (1) via role-based access or ACLs (1).
  • Accountability: logins and actions recorded in audit logs (1) so suspicious activity or disputes can be traced to an account (1).

                            

                            

                                
A secondary school has been hit by ransomware that encrypted student records and coursework. Discuss the measures the school should put in place to prevent and recover from a future attack.

                                

                                    
Indicative content:

                                    
    
                                        
  • Prevention: staff and student training on phishing; email filtering; anti-malware kept updated; regular patching; restrict admin rights; MFA; network segregation so admin systems are separate from student networks; disable USB autorun.
    • 
                                        
  • Recovery: regular backups stored offline/air-gapped or in immutable cloud storage so ransomware cannot encrypt them; test restores; documented recovery procedure; incident response plan.
    • 
                                        
  • Balance: cost and staff time for a school budget; training must be repeated; backups only help if tested; no single measure is enough.

Evaluate the measures the building society could introduce to improve its security.

    • 
                                        
  • Introducing MFA would mean that ...
    • 
                                        
  • Patching every six months is a risk because ...
    •

    •

Indicative content:

                                    
    
                                        
  • MFA: stolen passwords no longer enough; reduces account takeover from phishing; cost and user inconvenience.
    •

    •
