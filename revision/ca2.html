2.1 Standard data types

Every value in a program has a data type. The data type decides what the value can store and what you can do with it.

✗ COMMON MISTAKE

  • Phone numbers and postcodes are strings, not integers. You never do maths on them, and an integer would drop a leading zero (07700 becomes 7700).
  • "42" in quotes is a string. 42 without quotes is an integer. "4" + "2" gives "42", not 6.
  • Money is often stored as a float in exam answers, but floats can give tiny rounding errors: 0.1 + 0.2 gives 0.30000000000000004. Real payment systems often store pence as an integer.

✗ COMMON MISTAKE

  • int("3.5") crashes with a ValueError. Convert to float first: int(float("3.5")) gives 3.
  • bool("False") is True. Any non-empty string converts to True.
  • print("Total: " + 10) crashes with a TypeError. Use str(10) or an f-string.

Scope: global and local variables

Scope is the part of the program where a variable can be used.

  • A global variable is created outside any function. It can be read anywhere in the program.
  • A local variable is created inside a function. It only exists while the function is running and cannot be used outside it.
  • To change a global variable inside a function, Python needs the global keyword.
basket_total = 0            # global

def add_item(price):
    global basket_total
    discount = 0.1          # local: only exists inside add_item
    basket_total = basket_total + price * (1 - discount)

add_item(20)
add_item(10)
print(basket_total)

27.0
Global variablesLocal variables
BenefitsAvailable everywhere, so useful for values many parts of the program need (e.g. settings).Can't be changed by accident elsewhere. The same name can be reused in different functions. Memory is freed when the function ends. Functions are self-contained and easier to test and reuse.
DrawbacksAny function can change them, so bugs are hard to trace. Use memory for the whole run. Make functions depend on outside values.Values are lost when the function ends unless returned.

★ EXAM TIP

Good practice is to use local variables and pass values in as parameters and back out with return. If asked why, say: it reduces side effects, makes code easier to debug, and makes functions reusable.

Conditions are checked from the top. The first True one runs and the rest are skipped. That is why the highest boundary goes first: if mark >= 40 came first, 64 would get a Pass.

Selection: match / case (Python 3.10+)

match compares one value against several possible patterns. It is tidier than a long elif chain when you are checking a single value for exact matches, such as a menu choice.

choice = "2"
match choice:
    case "1":
        print("View basket")
    case "2":
        print("Checkout")
    case "3" | "q":
        print("Quit")
    case _:
        print("Invalid option")

Checkout

case _: is the default and works like else. | means 'or'. match cannot do range checks like mark >= 70 without extra syntax, so use if for those.

Check digit worked example: ISBN-13

Multiply the 13 digits alternately by 1 and 3 and add the results. If the total divides exactly by 10, the number is valid. A single mistyped digit or two swapped digits will usually fail.

def valid_isbn13(isbn):
    if len(isbn) != 13 or not isbn.isdigit():
        return False
    total = 0
    for i in range(13):
        weight = 1 if i % 2 == 0 else 3
        total = total + int(isbn[i]) * weight
    return total % 10 == 0

print(valid_isbn13("9780306406157"))

2.9 Design considerations and programming practices

Order of actions and operations (2.9.1–2.9.2, 2.9.4)

  • Actions must happen in a logical order: get input, validate it, process it, output the result. You cannot calculate a total before reading the prices.
  • Initialise variables before a loop. Setting total = 0 inside the loop resets it every time.
  • Use brackets so calculations follow the order you intend. This keeps outputs accurate and avoids logic errors.
  • Check for zero before dividing: if count > 0: average = total / count. This avoids a ZeroDivisionError.
  • For efficiency, do work once rather than inside a loop. Calculate len(items) once before the loop; put the most likely condition first in an if chain; stop a search as soon as the item is found.

Code style and readability (2.9.6)

  • Naming conventions: consistent names let any developer guess what a variable holds.
  • White space: blank lines between functions, spaces around operators (x = a + b), and consistent indentation make structure obvious. In Python, indentation is required, not optional.
  • Maximum line length: PEP 8 suggests 79 characters. Short lines can be read without scrolling sideways and are easier to compare side by side.

2.10 Robust code

Characteristics of robust code (2.10.1)

  • Handles unexpected inputs: validates input and re-prompts instead of crashing. Letters typed into a number field are rejected.
  • Handles unexpected terminations: uses try/except to catch runtime errors (missing file, network down, divide by zero) and closes files or saves data safely.

def read_total(filename):
    try:
        with open(filename, "r") as f:
            values = [float(line.strip()) for line in f]

    except FileNotFoundError:
        print(f"Error: '{filename}' was not found. Check the file name.")
    except ValueError:
        print(f"Error: '{filename}' contains a line that is not a number.")
    return None

Linear search

  1. Start at the first item.
  2. Compare it with the target.
  3. If it matches, stop and return the position.
  4. Otherwise move to the next item.
  5. If you reach the end without a match, the item is not there.
def linear_search(items, target):
    for i in range(len(items)):
        if items[i] == target:
            return i
    return -1

print(linear_search(["Leeds", "York", "Hull", "Wakefield"], "Hull"))
print(linear_search(["Leeds", "York"], "Bradford"))

Binary search

The list must be sorted first.

  1. Find the middle item.
  2. If it is the target, stop.
  3. If the target is smaller, discard the middle item and everything above it.
  4. If the target is larger, discard the middle item and everything below it.
  5. Repeat on the half that is left until the target is found or nothing is left.
def binary_search(items, target):
    low = 0
    high = len(items) - 1
    while low <= high:
        mid = (low + high) // 2
        if items[mid] == target:
            return mid
        elif target < items[mid]:
            high = mid - 1
        else:
            low = mid + 1
    return -1

numbers = [3, 8, 12, 19, 25, 31, 40, 47, 52]

Bubble sort

  1. Compare the first two items. If they are in the wrong order, swap them.
  2. Move along one place and compare the next pair. Repeat to the end of the list: this is one pass.
  3. After each pass the largest unsorted item has 'bubbled' to its correct place at the end.
  4. Repeat passes until a whole pass makes no swaps.
def bubble_sort(items):
    n = len(items)
    swapped = True
    while swapped:
        swapped = False
        for i in range(n - 1):
            if items[i] > items[i + 1]:
                items[i], items[i + 1] = items[i + 1], items[i]
                swapped = True
        n = n - 1
    return items

Insertion sort

  1. Treat the first item as a sorted list of one.
  2. Take the next item.
  3. Compare it with items in the sorted part, moving larger items one place right, until you find where it belongs.
  4. Insert it. Repeat until every item has been inserted.
def insertion_sort(items):
    for i in range(1, len(items)):
        current = items[i]
        j = i - 1
        while j >= 0 and items[j] > current:
            items[j + 1] = items[j]
            j = j - 1
        items[j + 1] = current
    return items

Merge sort

  1. Split the list in half, then split each half again, until every list has one item (a list of one is sorted).
  2. Merge pairs of lists back together: compare the front item of each list and take the smaller one each time.
  3. Keep merging until there is one sorted list.
def merge_sort(items):
    if len(items) <= 1:
        return items
    mid = len(items) // 2
    left = merge_sort(items[:mid])
    right = merge_sort(items[mid:])
    merged = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i])
            i = i + 1
        else:
            merged.append(right[j])
            j = j + 1
    merged = merged + left[i:] + right[j:]
    return merged

print(merge_sort([38, 27, 43, 3, 9, 82, 10]))

★ EXAM TIP: JUDGING SUITABILITY (2.11.6–2.11.7)

A logistics company keeps a list of 250,000 parcel tracking numbers. New parcels are added throughout the day and customers search for their parcel thousands of times per hour. Evaluate the use of linear search and binary search for this system, including how the data should be sorted.

Indicative content. Credit other valid points.

  • Linear search works on unsorted data, so new parcels can simply be appended with no sorting cost.
  • Linear search is slow here: worst case 250,000 comparisons, average about 125,000, repeated thousands of times per hour, so slow responses and high server load.
  • Binary search needs about 18 comparisons in the worst case for 250,000 items, so it is far faster for frequent searches.
  • Binary search requires the list to be sorted; sorting takes time, but this cost is paid once rather than on every search.
  • New parcels could be inserted into the correct position as they arrive (insertion sort is efficient for one new item into a sorted list), or added in batches and the list re-sorted with merge sort overnight.
  • Merge sort is fast on large data but needs extra memory; a server is likely to have enough.
  • Judgement: binary search on a sorted list is the better choice because searches far outnumber insertions; the extra complexity is justified.
