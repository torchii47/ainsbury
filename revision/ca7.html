BenefitsDrawbacks

Physical topology is how devices are actually cabled. Logical topology is how data actually flows. For example, a network can be physically wired as a star but data may be passed in a logical bus or ring pattern; Wi-Fi devices have no cables but logically form a star around the access point.

7.3.9–11 Packets, protocols, bandwidth and latency

Data packets (7.3.9)

PartContentsRole
HeaderSource IP address; destination IP address; packet sequence number; total number of packets; protocol; time to live (TTL)Gets the packet to the right place and lets the receiver reassemble packets in order. TTL stops lost packets circulating forever.
PayloadThe actual data being sent (a chunk of the file, email or web page)The content.
TrailerError-checking value (e.g. CRC) and end-of-packet markerLets the receiver detect whether the packet was corrupted.

Packet switching

  1. Data is split into packets, each with a header.
  2. Each packet is sent independently; routers forward each one along the best available route at that moment.
  3. Packets may take different routes and arrive out of order.
  4. The receiver uses the sequence numbers to reassemble them.
  5. Missing or corrupted packets are requested again (TCP).

Benefits: efficient use of the network; routes around failures and congestion. Drawbacks: packets can arrive out of order or be delayed, which matters for real-time traffic like video calls.

Causes of packet loss

  • Network congestion: routers' buffers fill up and packets are dropped.
  • Faulty or damaged hardware (cables, routers, NICs).
  • Wireless interference or weak signal.
  • TTL reaching zero before arrival.
  • Software bugs or misconfigured devices; deliberate attacks such as DoS.

Error handling: cyclic redundancy check (CRC)

  1. The sender performs a calculation (a form of polynomial division) on the packet's data to produce a CRC value.
  2. The CRC value is added to the trailer.
  3. The receiver performs the same calculation on the data it received.
  4. If the values match, the data is accepted. If not, the packet is corrupt and is discarded and re-requested.

✎ WORKED EXAMPLE: DOWNLOAD TIME

  • How long will a 500 MB file take to download on a 100 Mbps connection?
  • Convert megabytes to megabits: 500 × 8 = 4,000 Mb.
  • Time = data ÷ bandwidth = 4,000 ÷ 100 = 40 seconds (in ideal conditions; real throughput is usually lower).

Key features (7.4.2)

FeatureMeaning
Increased securityVMs are separated, so malware in one VM does not easily spread to others or the host; snapshots allow quick recovery.
Managed executionThe hypervisor controls each VM's access to resources (CPU, RAM, storage), so VMs run in a controlled way.
SharingSeveral VMs share one set of physical hardware.
AggregationResources from several physical machines are combined to act as one larger pool (e.g. a cluster).
EmulationA VM can imitate different hardware or an older OS, so legacy software can still run.
IsolationEach VM is independent: a crash in one does not affect the others.
PortabilityA VM is stored as files, so it can be copied, backed up or moved to another host easily.

Benefits and drawbacks (7.4.3–7.4.4)

BenefitsDrawbacks
  • Cost effective for large environments: fewer physical servers, less space, power and cooling
  • Easy management: VMs created, cloned and monitored from one console
  • Resilience: VMs can move to another host if one fails
  • Potentially lower carbon footprint: fewer machines running
  • Improved disaster recovery: VM files can be backed up and restored quickly
  • Better testing environments: test software on different OSs safely; roll back with snapshots
  • Education and training: students can practise on VMs without damaging real systems
  • Extra hardware load: the hypervisor uses resources, and the host needs plenty of RAM and CPU
  • Slower execution time than running directly on hardware
  • Potential for false representation of performance: software tested in a VM may perform differently on real hardware
  • If the physical host fails, all its VMs go down unless failover is set up
Virtual machine (VM)
A software-based computer that runs an operating system and applications like a physical machine.
Hypervisor
Software that creates and runs virtual machines and shares physical hardware between them.

7.6 Resilient digital environments

Benefits of resilience (7.6.1)

BenefitImpact on organisation and clients
Increased security: data security in storage and transfer; reduced vulnerabilitiesData is protected from loss and attack; fewer weaknesses for attackers to exploit.
Increased reputation: protect brand/image; retain customer confidenceCustomers trust an organisation whose services are reliable and whose data is safe.
Reduction in downtimeServices stay available, so sales, productivity and customer service continue.

Methods to improve resilience (7.6.2)

MethodDetail
Software updates / upgradesPlanned updates and upgrades on a schedule (tested first, outside busy hours). Patches released quickly in response to new vulnerabilities.
Hardware replacementRolling replacement plans: replace a proportion of hardware each year so nothing becomes too old and costs are spread. Secure disposal: wipe or physically destroy drives so data cannot be recovered; use certified recyclers.

Backup systems and recovery proceduresOnsite: fast to restore but at risk from the same fire or theft. Remote/offsite: protected from local disasters but slower to restore. Cloud: automatic, offsite, scalable; depends on internet and provider. Recovery procedures must be documented and tested.

✎ WORKED EXAMPLE

An online bank cannot afford any downtime, so a hot site is justified despite the cost. A small accountancy firm could use cloud backups and a cold site (or simply work from home), because a few days' disruption is tolerable and the cost of a hot site would be out of proportion.

Exam-style questions

Allow about 100 minutes.

State two features of an embedded device.

  • Any two: performs one dedicated function; built into a larger device; low power; small; firmware stored in ROM; limited or no user interface; often real-time.

Explain why increasing the cache size of a processor can improve performance.

  • Cache stores frequently used instructions/data close to the CPU (1) so the CPU waits less for data from slower RAM / fewer RAM accesses (1).

Compare RAM and ROM.

  • RAM is volatile; ROM is non-volatile (1).
  • RAM can be read and written; ROM is normally read only (1).
  • RAM holds programs and data currently in use; ROM holds startup instructions / firmware / BIOS (1).
  • RAM is usually much larger than ROM (1).

A delivery company needs laptops for drivers who work outdoors. Explain why solid state storage is more suitable than magnetic storage.

  • Point (1) + linked explanation (1), twice. E.g. no moving parts (1) so less likely to be damaged if the laptop is dropped or vibrates in a van (1); uses less power (1) so battery lasts longer on shift (1); faster access (1) so apps load quickly at each delivery (1).

Describe how a multitasking operating system allows several programs to appear to run at the same time.

  • The CPU switches rapidly between tasks (1)
  • each task is given a time slice (1)
  • switching is so fast that programs appear to run simultaneously; interrupts allow urgent tasks to take priority (1).

Explain two differences between a compiler and an interpreter.

  • Difference (1) + expansion (1), twice. E.g. a compiler translates the whole program at once (1) producing an executable, whereas an interpreter translates and runs line by line (1); compiled code runs faster (1) because translation is done in advance (1); interpreter stops at the first error (1) making debugging easier (1); compiled program can be distributed without source code (1) whereas interpreted needs the source and interpreter (1).

State the purpose of each protocol: (a) DHCP (b) DNS (c) IMAP.

  • (a) Automatically assigns IP addresses (and other settings) to devices joining a network (1).
  • (b) Translates domain names into IP addresses (1).
  • (c) Retrieves email while keeping it on the server, synchronised across devices (1).

Describe the role of the transport layer in the TCP/IP model.

  • Any three: splits data into segments/packets; numbers them so they can be reassembled; establishes the connection between hosts (TCP); uses port numbers to direct data to the correct application; checks for errors and requests retransmission; flow control.

Explain how a cyclic redundancy check is used to detect errors in a data packet.

  • Sender calculates a CRC value from the data and adds it to the packet trailer (1).
  • Receiver performs the same calculation on the received data (1).
  • If the values do not match the packet is corrupt and is discarded / re-sent (1).

A user has a fast broadband connection but experiences lag in online games. Explain the likely cause.

  • High latency (1) caused by e.g. distance to the game server, congestion, Wi-Fi interference or many hops, so there is a delay even though bandwidth is high (1).

Calculate how long it would take to transfer a 2 GB file over a 50 Mbps connection. Show your working. (1 GB = 1,000 MB)

  • 2 GB = 2,000 MB = 16,000 Mb (1)
  • 16,000 ÷ 50 (1)
  • = 320 seconds (5 minutes 20 seconds) (1). Accept 2 GB = 2,048 MB giving 327.68 seconds.

Explain the difference between a type 1 and a type 2 hypervisor.

  • Type 1 runs directly on the hardware with no host OS (1); type 2 runs as an application on top of a host OS (1).
  • Type 1 is more efficient/faster/more secure, used in data centres (1); type 2 is easier to set up, used for testing/learning on a PC (1).

A start-up wants to deploy a web application without managing servers or operating systems. Identify the most suitable cloud delivery model and justify your choice.

  • PaaS (1).
  • The provider manages hardware, virtualisation, OS and runtime (1)
  • so the start-up only manages its application code and data, saving time and needing fewer skilled staff (1).

Explain two methods a hospital could use to improve the resilience of its patient record system.

  • Method (1) + linked explanation (1), twice. E.g. redundancy: duplicate servers with failover (1) so records are still available if one fails (1); regular backups stored offsite/cloud (1) so data can be restored after ransomware or fire (1); hot site (1) so service continues within minutes after a disaster (1); patching (1) to close vulnerabilities (1); device hardening (1); SOPs and staff training (1).

A college with three buildings is redesigning its network. Discuss the suitability of star and mesh topologies for the network.

Indicative content:

  • Star within each building: easy to add devices; one cable fault affects only one device; good performance; but the central switch is a single point of failure.
  • Mesh between buildings: multiple routes, so if one link between buildings fails traffic is rerouted; high resilience; but more expensive cabling (fibre between buildings) and more complex.
  • A combination is likely: star in each building, partial mesh or tree linking them. Tree is simpler and cheaper but the root is a single point of failure.
  • Consider budget, need for resilience (e.g. exams, online learning), and scalability.

A national chain of 40 gyms runs its booking, membership and payment systems on old servers in its head office. It is considering moving to a public cloud using SaaS for membership and IaaS for its booking system. Evaluate this plan.

◆ SUPPORT: SENTENCE STARTERS

  • A star topology would suit each building because ... However, ...
  • A mesh would provide more routes between buildings, which means ...
  • Moving to the cloud would give the gym chain elasticity, so at busy times such as January ...
  • With IaaS the gym chain would still be responsible for ...
  • A risk of the public cloud is ...

Indicative content:

  • Benefits: no need to replace old servers; elasticity for busy periods (January, evening bookings); access from all 40 gyms and members' phones; provider's data centres offer redundancy and backups, improving resilience; predictable subscription costs; SaaS membership software is maintained and updated by the provider.
  • Shared responsibility: with IaaS the gym chain still manages the OS, runtime, booking application, data and user accounts, so it needs skilled staff; with SaaS it only manages users and data.
  • Drawbacks: dependent on internet connection at every gym; ongoing costs may exceed owning servers over time; data held by a third party, possibly abroad, so data protection checks needed (payment data must meet PCI DSS); migration risk and staff training; vendor lock-in; less control over SaaS customisation.
  • Could suggest PaaS for the booking system to reduce management burden.
  • Judgement: e.g. the plan is suitable because old servers are a resilience risk and cloud offers scalability and redundancy, provided the chain has reliable internet at each site and checks where data is stored.
