Content Area 6: Data

Content area 6 covers what data is, where it comes from, how it is categorised, stored, formatted, checked, transformed, accessed and analysed. Many questions ask you to choose a format, model, data type or method for a scenario and justify it, so learn the benefits and drawbacks as well as the definitions.

6.1 Data, information and knowledge

Sources of data (6.1.2)

SourceExamplesPoints to note
HumansSurveys, online forms, feedbackSubject to errors, bias and dishonesty; can capture opinions
AI / machine learningPredictions, recommendations, generated contentDanger of feedback loops: if AI outputs are fed back as training data, errors and bias are reinforced (e.g. predictive policing sending officers to the same areas, which produces more recorded crime there)
SensorsTemperature, accelerometer, vibration, sound, light, pressureContinuous, automatic, accurate if calibrated; huge volumes
Internet of ThingsSmart thermostats, lights, security cameras, trackersReal-time data from many devices; privacy and security concerns
TransactionsCustomer data, membership, timing, basket contentsShows real behaviour; used for stock control and marketing

Ethical data practices and the value of data (6.1.3)

Ethical practice means collecting only what is needed, being transparent, getting consent, keeping data secure, avoiding bias, and following data protection law. The value of data is judged by:

MetricQuestion to ask
QuantityIs there enough data to draw reliable conclusions? (More is not always better if it is poor quality.)
TimeframeIs it recent enough? Last year's prices may be useless today.
SourceWhere did it come from? Is the source reliable and was it collected ethically?
VeracityIs it accurate and trustworthy?

UseExample
Analysis to identify patternsSupermarket sees barbecue food sells out when the forecast is sunny
System performance analysis: load, outage, throughput, statusIT team monitors server load and outages to plan upgrades
User monitoring: login/logout, resources accessedSpot unusual logins at 3am; check who opened a sensitive file
Targeted marketing: discounts, upselling'Customers who bought this also bought...'; personalised vouchers

Data
Raw facts and figures with no context, e.g. 18, 22, 25.
Information
Data that has been processed and given context so it has meaning, e.g. 'Temperatures in Leeds this week: 18–25°C'.
Knowledge
Understanding gained from information that can be applied to make decisions, e.g. 'Ice cream sales rise above 20°C, so order more stock'.
Feedback loop (AI)
When an AI system's outputs influence the data it is later trained on, which can reinforce errors or bias.
Veracity
How accurate and trustworthy data is.

■ INTERRELATIONSHIPS (6.4.2–6.4.4)

  • Structured data uses specific data types (integer, date) so it can be calculated, sorted and validated. Unstructured data is often stored as a Blob or long string.
  • The data type controls what transformations are possible: you can average integers but not strings; you can sort dates chronologically only if stored as a date, not as text.
  • Choosing the wrong type causes problems: phone numbers stored as integers lose the leading 0.

JSON and CSV in Python

import json
import csv

order = {"id": 1042, "customer": "Asha",
         "items": ["latte", "scone"], "paid": True}

text = json.dumps(order)              # Python dictionary -> JSON string
print(text)
back = json.loads(text)               # JSON string -> dictionary
print(back["items"][1])

with open("orders.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["order_id", "customer", "total"])
    writer.writerow([1042, "Asha Patel", 5.40])

with open("orders.csv") as f:
    for row in csv.reader(f):
        print(row)

Structures for storing data (6.6)

StructureDefinitionWhen used
MetadataData about data: describes and gives context, e.g. author, date created, file size, GPS location, column names and types.Searching and organising files; understanding what a data set contains; but can leak private information (photo location)
File-basedData stored in individual separate files, each managed by the program that uses it.Small systems, single-user apps, logs. Simple but leads to duplication and inconsistency across files.
Directory-basedFiles organised into folders (directories) by category.Organising documents on a shared drive or project folder; easy to navigate and set permissions per folder.
Hierarchy-basedData organised as a tree of parent–child levels, each item with one parent (folders within folders, XML, organisation charts).Data with a natural one-to-many structure; fast to navigate down a known path; awkward for many-to-many relationships.

Interrelationship (6.6.4): the storage structure affects how easily data can be transformed. Data scattered across separate files must be merged before analysis; hierarchical data may need flattening into rows before it can go in a CSV or spreadsheet.

JSON
JavaScript Object Notation: a lightweight text format storing data as key–value pairs and arrays, widely used by web APIs.
CSV
Comma-separated values: a plain text format where each line is a record and fields are separated by commas.
XML
Extensible Markup Language: a text format that uses custom tags to describe and structure data.
ASCII
A character set using 7 bits to represent 128 characters (English letters, digits, symbols, control codes).
UTF-8
A variable-length Unicode encoding (1–4 bytes per character) that can represent characters from every language and emoji, and is backwards compatible with ASCII.
Metadata
Data about data, e.g. a photo's date, location, file size and camera model.

6.7 Big Data, quality and maintenance

Big Data is data that is too large, fast or varied for traditional tools to handle. It has multiple dimensions, the six Vs:

VMeaningImpact on gathering, storing, maintaining and processing
VolumeThe amount of dataNeeds scalable storage (cloud, data lakes) and distributed processing
VarietyDifferent types and formats: structured, unstructured, images, sensor readingsNeeds flexible storage; harder to combine and analyse
VariabilityData flow and meaning change over time (seasonal peaks; words changing meaning)Systems must handle peaks; analysis must account for changing context
VelocityThe speed data arrives and must be processedNeeds real-time processing and fast networks (e.g. fraud detection)
VeracityAccuracy and trustworthinessNeeds cleaning and validation; poor data leads to poor decisions
ValueHow useful the data is to the organisationStoring data costs money; only worth keeping if it delivers insight

Data quality assurance methods (6.7.4)

MethodMeaningExample
ValidationAutomatic check that data is sensible and follows rulesAge must be 16–99; email must contain @
VerificationCheck that data has been entered or copied accuratelyEnter password twice; proofread against the original form
ReliabilityData comes from a trustworthy source and gives consistent results when collected againCalibrated sensors; reputable data suppliers
ConsistencyData is the same across systems and uses the same formatsDates all in DD/MM/YYYY; customer address the same in sales and delivery systems
IntegrityData stays accurate and complete and isn't corrupted or altered without authorisationForeign keys must match an existing record; checksums; access control
RedundancyControl of duplicate data: remove unplanned duplicates; plan duplicates for backupRemove duplicate customer records; keep a replicated copy for disaster recovery

Factors that affect maintenance (6.7.5): time (cleaning and updating data takes staff time), skills (specialists such as data engineers are needed for large data sets), cost (storage, software, staff, training).

Big Data
Data sets so large, fast-moving or varied that traditional tools can't process them; described by the six Vs.
Verification
Checking data has been entered or transferred accurately, e.g. double entry or proofreading.
Data integrity
Data remains accurate, complete and consistent throughout its life.
Data redundancy
The same data stored in more than one place. Unplanned redundancy causes inconsistency; planned redundancy (backups) improves resilience.

A chain of gyms wants to analyse membership, attendance and payment data from 40 sites. Discuss the suitability of a data warehouse and a data lake.

Indicative content:

  • Warehouse: structured, cleaned data from all sites; consistent reporting for managers (attendance trends, revenue); data must be wrangled first, which takes time and skill; good fit because the data is mostly structured.
  • Lake: stores raw data cheaply in any format, including CCTV or app logs; flexible for future analysis; but harder to query, risk of becoming a 'data swamp', needs specialist skills.
  • Could use both: lake for raw data, warehouse/marts for reporting.

A hospital is choosing between a hierarchical and a relational data model for patient, ward, doctor and appointment data. Evaluate which model is more suitable.

◆ SUPPORT: SENTENCE STARTERS

  • A data warehouse would suit the gym chain because the data is ... However, ...
  • In a hierarchical model each patient would have only one ... which is a problem because ...
  • A relational model links tables using ...

Indicative content:

  • Hierarchical: simple; fast for one-to-many paths, e.g. ward → patients; but a patient may see many doctors and a doctor has many patients (many-to-many), forcing duplication; changes are difficult; inconsistent data risk.
  • Relational: tables for patients, doctors, wards, appointments linked by keys; appointments resolve the many-to-many relationship; reduces duplication and inconsistency; flexible queries (e.g. all appointments for a doctor this week); integrity enforced by foreign keys; more complex to design; joins on very large data can be slower.
  • Judgement: relational is more suitable because hospital data has many-to-many relationships and needs accuracy and flexible querying; integrity is critical for patient safety.
