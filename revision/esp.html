1. Import a CSV into a data frame

A data frame is a table: rows are records, columns are fields. pd.read_csv() turns a CSV file into one, and works out the data types for you.

import pandas as pd

with open("sales.csv", "w") as f:
    f.write("date,branch,item,quantity,price\n")
    f.write("2027-05-03,Leeds,Latte,12,3.20\n")
    f.write("2027-05-03,York,Tea,8,1.80\n")
    f.write("2027-05-04,Leeds,Scone,5,2.50\n")
    f.write("2027-05-04,York,Latte,9,3.20\n")
    f.write("2027-05-05,Leeds,Latte,15,3.20\n")
    f.write("2027-05-05,York,Scone,11,2.50\n")

★ EVERY GRAPH NEEDS

  • A title that says what the graph shows: plt.title()
  • Labelled axes, with units: plt.xlabel() and plt.ylabel()
  • A legend whenever there's more than one line or bar colour: plt.legend()
  • The right type: a line graph for trends over time, a bar chart to compare categories (6.9)

This program should keep asking for an age until it is between 16 and 99. Explain the two defects and write a corrected version.

age = int(input("Age: "))
while age < 16 or age > 99:
    print("Age must be 16 to 99")
print("Accepted")
  • The loop never asks again, so an invalid age prints the message forever: an infinite loop (logic) (1). Ask for the age inside the loop (1).
  • Typing a word such as ten crashes int() with a ValueError (runtime) (1). Check the input is a whole number before converting it, e.g. with isdigit() or try/except (1).
while True:
    entry = input("Age: ")
    if not entry.isdigit():
        print("Enter a whole number")
    elif not 16 <= int(entry) <= 99:
        print("Age must be 16 to 99")
    else:
        break
print("Accepted:", entry)

★ A METHOD FOR FIXING DEFECTS

  1. Read what the code is meant to do, then run it.
  2. If it crashes, read the error: the last line gives the type, the line number shows where.
  3. If it runs but the answer is wrong, trace it with a trace table or add print statements.
  4. Fix one defect at a time and re-run after each fix.
  5. Test with valid, boundary, invalid and erroneous data (2.12), and record what you changed and why.

Writing a reflective evaluation

An evaluation judges how well your solution meets the brief and what you'd do differently. Like an 'evaluate' exam question, it needs evidence, both strengths and weaknesses, and a supported judgement.

CoverQuestions to answer
Meeting the requirementsGo through the brief. Which requirements does your solution meet fully, partly or not at all? Use your test results as evidence.
Quality of the solutionUse the criteria from 2.9.7: efficiency, data structures and types, variables and constants, presentation, maintainability, robustness.
UsersIs it usable and accessible for the users in the scenario? (3.1.3)
Legal and securityDoes it handle personal data properly and protect it? (4.1.3, CA8)
Your processHow did your planning and testing go? What would you do differently next time?
ImprovementsWhat would you add or change with more time, and why would it help the client?

◆ SUPPORT: SENTENCE STARTERS

  • The solution meets the requirement to ... because test ... showed ...
  • A limitation is that ... which means the client ...
  • I chose a dictionary for ... because ... However, ...
  • If I had more time, I would ... so that ...
  • Next time I would plan ... earlier, because ...
  • Overall, the solution is ... because ... outweighs ...

✗ COMMON MISTAKES

  • Describing what you did instead of judging how well it works.
  • Only listing strengths. A balanced evaluation earns more.
  • Claims with no evidence. Point to a test, a requirement or a feature.
  • Improvements with no reason. Say why each one would help the client or users.
