One line of high-level code usually becomes several machine code instructions. One line of assembly becomes one machine code instruction.

Translators

The CPU can only execute machine code. A translator converts code written by a programmer (source code) into machine code. There are three types:

CompilerInterpreter
How it worksTranslates the whole program into machine code in one go, producing an executable fileTranslates and runs the program one line at a time
ErrorsReports all the errors after trying to compile the whole program; no executable is made until they're fixedStops as soon as it reaches an error, showing the line, so errors are easy to find
Running the programThe executable runs quickly, without the compiler or source codeSlower: every line is translated every time it runs; the interpreter is needed every time
SharingThe executable can be shared without giving away the source codeThe source code must be shared, so it can be copied or changed
Best forFinished programs that are distributed to usersDeveloping and testing, learning to program

An assembler translates assembly language into machine code.

An interpreter stops at the first error

program = ["x = 5", "print(x * 2)", "print(y)", "print('never reached')"]
for number, line in enumerate(program, start=1):
    try:
        exec(line)
    except NameError as error:
        print("Error on line", number, ":", error)
        break

A compiler checks everything first

program = ["x = 5", "print(x * 2", "y = = 3", "print('done')"]
errors = 0
for number, line in enumerate(program, start=1):
    try:
        compile(line, "program", "exec")
    except SyntaxError:
        print("Syntax error on line", number)
        errors = errors + 1
if errors > 0:
    print(errors, "errors: no executable file is made")

High-level language
A programming language with English-like statements that is portable and easy to read, e.g. Python.
Low-level language
A language close to machine code, such as assembly or machine code, written for a specific CPU.
Machine code
Binary instructions that the CPU can execute directly.
Assembly language
A low-level language that uses short mnemonics, each translating to one machine code instruction.
Translator
A program that converts source code into machine code.
Compiler
A translator that converts the whole program into machine code at once, producing an executable file.
Interpreter
A translator that translates and executes a program one line at a time.
Assembler
A translator that converts assembly language into machine code.

2.5.2 The Integrated Development Environment (IDE)

An IDE is software that gives programmers the tools to write, translate, run, test and debug programs in one place, e.g. IDLE, Thonny, Visual Studio Code, PyCharm.

ToolFeaturesHow it helps
EditorSyntax highlighting (colours for keywords, strings, comments); automatic indentation; auto-complete; line numbers; bracket matchingCode is quicker to write and easier to read; mistakes like a missing bracket stand out
Error diagnosticsHighlights errors; error messages with the line number and type of error; suggests fixesErrors are found and fixed quickly
Run-time environmentRuns the program inside the IDE; shows its output and lets you enter input; reports run-time errors (crashes)The program can be tested without leaving the IDE
TranslatorA built-in compiler and/or interpreterCode can be translated and run with one click
Debugging toolsBreakpoints pause the program at a chosen line; stepping runs one line at a time; variable watch shows the values of variables as it runsLogic errors can be tracked down by seeing exactly where values go wrong (like an automatic trace table)

★ EXAM TIP: NAME THE TOOL AND SAY WHAT IT DOES

"Breakpoints" alone gets 1 mark. "Breakpoints stop the program at a set line, so the programmer can check the values of the variables at that point to find a logic error" gets 2.

IDE
Integrated Development Environment: software providing tools to write, run, test and debug programs.
Syntax highlighting
An editor feature that colours different parts of the code, such as keywords and strings, to make it easier to read.
Error diagnostics
IDE tools that detect errors and report them, usually with a line number and a description.
Run-time environment
A feature that lets a program run within the IDE, showing its output and any run-time errors.
Breakpoint
A marker that pauses a program at a chosen line so its state can be inspected.

Exam-style questions

Allow about 20 minutes. Answer each question before you look at its mark scheme.

Give two characteristics of a high-level language.

  • Any two: uses English-like keywords; easy for humans to read/write; portable across different CPUs; must be translated before running; one statement becomes many machine code instructions; programmer doesn't need to know about the hardware.

Explain why a programmer might write part of a program in a low-level language.

  • Gives direct control of the hardware/memory (1) so the code can run faster / use less memory, e.g. in an embedded system or device driver (1).

State why programs written in a high-level language must be translated.

  • The CPU can only execute machine code/binary (1).

Describe two differences between a compiler and an interpreter.

  • Compiler translates the whole program at once; interpreter translates one line at a time (2).
  • Compiler produces an executable file; interpreter doesn't (2). Accept: compiler reports errors at the end / interpreter stops at the first error; compiled code runs faster.

A games company is about to sell its finished game. Explain why it should use a compiler.

  • It produces an executable that can be distributed without the source code (1) so the code can't easily be copied/changed by others / the game runs faster / users don't need the translator (1).

Describe two features of an IDE that help a programmer to find and fix errors.

  • Any two features with descriptions, 2 marks each: error diagnostics highlight errors and give line numbers/messages; breakpoints pause the program at a line to inspect variables; stepping runs one line at a time; variable watch shows values as the program runs; syntax highlighting shows mistyped keywords/unclosed strings.

State the purpose of an assembler.

  • Translates assembly language (1) into machine code (1).
