1.2.1 Primary storage (memory)

Primary storage is memory the CPU can access directly. It is needed because the CPU has to fetch instructions and data from somewhere fast: secondary storage is far too slow to work from directly.

RAM (random access memory)ROM (read only memory)
Volatile?Volatile: contents are lost when the power is turned offNon-volatile: contents are kept without power
Read / writeCan be read from and written toCan only be read (normally can't be changed)
PurposeHolds the operating system, programs and data currently in useHolds the start-up instructions (the BIOS / boot program) the computer needs when it is switched on
SizeLarge, e.g. 8–32 GBSmall, e.g. a few MB

Virtual memory

When RAM is full, the operating system uses part of secondary storage as if it were RAM. This is virtual memory.

1RAM fills up with open programs
→
2Data not being used right now is moved to virtual memory on the hard drive / SSD
→
3That frees space in RAM for the program in use
→
4When needed again, the data is swapped back into RAM

Why it's needed: so the computer can keep running more programs than fit in RAM, instead of crashing. Drawback: secondary storage is much slower than RAM, so moving data back and forth slows the computer down. Lots of swapping ("disk thrashing") makes it very slow. The fix is to add more RAM.

Primary storage
Memory that the CPU can access directly, such as RAM, ROM and cache.
RAM
Random access memory: volatile memory that holds the operating system, programs and data currently in use.
ROM
Read only memory: non-volatile memory that holds the start-up (boot) instructions.
Volatile
Memory that loses its contents when the power is switched off.
Virtual memory
Part of secondary storage used as extra RAM when RAM is full.

1.2.2 Secondary storage

Secondary storage is needed because RAM is volatile: files, programs and the operating system must be kept permanently (non-volatile) when the computer is off. It also holds far more than RAM.

1.2.3 Units and file sizes

Computers store everything in binary (1s and 0s) because they are made of billions of tiny switches (transistors) that can only be on or off. All data (numbers, text, images, sound, instructions) must be converted to binary to be processed.

File size formulas

FileSize in bits =
Imagecolour depth × image height (px) × image width (px)
Soundsample rate (Hz) × bit depth × duration (s)
Textbits per character × number of characters
✎ WORKED EXAMPLE: an image is 200 × 100 pixels with a colour depth of 8 bits. Calculate its size in KB. Try it, then click.

bits = 8 × 100 × 200 = 160,000 bits. bytes = 160,000 ÷ 8 = 20,000 bytes. KB = 20,000 ÷ 1,000 = 20 KB.

✎ WORKED EXAMPLE: a 10-second sound clip is sampled at 1,000 Hz with a bit depth of 4 bits. Calculate its size in bytes.

bits = 1,000 × 4 × 10 = 40,000 bits. bytes = 40,000 ÷ 8 = 5,000 bytes (5 KB).

✎ WORKED EXAMPLE: how many 2 MB photos fit on a 4 GB memory card?

4 GB = 4,000 MB. 4,000 ÷ 2 = 2,000 photos.

Check it in Python

# Image: colour depth x height x width
width, height, colour_depth = 800, 600, 24
image_bits = colour_depth * height * width
print("Image:", image_bits / 8 / 1000, "KB")

# Sound: sample rate x bit depth x duration
sample_rate, bit_depth, seconds = 44100, 16, 30
sound_bits = sample_rate * bit_depth * seconds
print("Sound:", sound_bits / 8 / 1000 / 1000, "MB")

# Text: bits per character x number of characters
characters, bits_per_char = 2000, 8
print("Text:", characters * bits_per_char / 8, "bytes")

Sound: 2.646 MB
Text: 2000.0 bytes

✗ COMMON MISTAKE

  • Forgetting to divide by 8 to get from bits to bytes.
  • Mixing up b (bit) and B (byte): 8 Mb = 1 MB.
  • Multiplying instead of dividing when going to a bigger unit.

1.2.4 Numbers: binary and hexadecimal

Denary ↔ binary (up to 8 bits, 0–255)

Each column in binary is worth double the one to its right.

1286432168421Denary
0110001064 + 32 + 2 = 98
11111111255 (the largest 8-bit number)

Denary to binary: work left to right. If the column value fits into what's left, write 1 and subtract it; otherwise write 0. E.g. 98: 128 no (0), 64 yes (1, 34 left), 32 yes (1, 2 left), 16 no, 8 no, 4 no, 2 yes (1, 0 left), 1 no → 01100010.

Hexadecimal (base 16)

Hex uses 0–9 then A=10, B=11, C=12, D=13, E=14, F=15. Two hex digits represent one byte (00 to FF = 0 to 255). Programmers use hex because it is shorter and easier for humans to read and remember than binary, with fewer errors when copying it, and it converts easily to binary. Used for colour codes (#FF5FA2), MAC addresses and error codes.

ConversionMethodExample
Hex → denaryFirst digit × 16, plus second digit3C = 3 × 16 + 12 = 60
Denary → hexDivide by 16: the whole number is the first digit, the remainder the second200 ÷ 16 = 12 r 8 → C8
Binary → hexSplit into two nibbles; convert each nibble (8 4 2 1) to one hex digit1011 0110 → 11, 6 → B6

Binary addition and overflow

RuleAnswer
0 + 00
0 + 1 or 1 + 01
1 + 10, carry 1
1 + 1 + 11, carry 1

Overflow happens when the result of a calculation needs more bits than are available, e.g. adding two 8-bit numbers gives a 9-bit answer. The extra bit is lost, so the stored result is wrong. 182 + 99 = 281, which is more than 255.

Binary shifts

ShiftEffectExample
Left shift by nMultiplies by 2ⁿ (bits move left, 0s fill on the right)00010110 (22) left 2 → 01011000 (88) = 22 × 4
Right shift by nDivides by 2ⁿ, losing any remainder (bits move right, 0s fill on the left)00010110 (22) right 1 → 00001011 (11) = 22 ÷ 2

Bits shifted off either end are lost, so a left shift can cause overflow and a right shift loses precision (e.g. 11 right 1 → 5, not 5.5).

def to_binary(number):
    bits = ""
    for place in [128, 64, 32, 16, 8, 4, 2, 1]:
        if number >= place:
            bits = bits + "1"
            number = number - place
        else:
            bits = bits + "0"
    return bits

for n in [5, 98, 255]:
    print(n, "=", to_binary(n))

a = 0b10110110   # 182
b = 0b01100011   # 99
total = a + b
print(to_binary(a), "+", to_binary(b), "=", format(total, "b"))
if total > 255:
    print("Overflow: the answer needs", total.bit_length(), "bits")

x = 0b00010110   # 22
print("Left shift 2:", to_binary((x << 2) & 255), "=", (x << 2) & 255)
print("Right shift 1:", to_binary(x >> 1), "=", x >> 1)
print("Hex of 98:", format(98, "02X"), "| denary of 3C:", int("3C", 16))

1.2.4 Characters

A character set is a defined list of characters recognised by the computer, each with a unique binary code. Codes are logically ordered: if you know 'A' is 65, then 'B' is 66 and 'E' is 69.

ASCIIUnicode
Bits per character7 bits (extended ASCII: 8 bits)16 or 32 bits (variable)
Number of characters128 (extended: 256)Over 1 million possible
CoversEnglish letters, digits, punctuation and control codesAlmost every language in the world, maths symbols, emoji
DrawbackCan't represent other alphabets (e.g. Arabic, Chinese)Files take more storage space

The more bits per character, the more different characters can be represented: n bits gives 2ⁿ characters. 7 bits → 128; 8 bits → 256; 16 bits → 65,536.

1.2.4 Images and sound

Images

A bitmap image is a grid of pixels (picture elements). Each pixel's colour is stored as a binary number.

TermMeaningIf it increases...
Colour depthThe number of bits used for each pixelMore colours can be shown (n bits = 2ⁿ colours), so better quality, but a larger file
ResolutionThe number of pixels in the image (width × height), or pixels per inchMore detail, sharper image, but a larger file
MetadataData about the image stored in the file: width, height, colour depth, date taken, camera, locationNeeded so the computer can display the image correctly

Sound

Sound is an analogue wave. To store it, the computer measures (samples) the amplitude of the wave at regular intervals and stores each measurement as a binary number.

TermMeaningIf it increases...
Sample rateThe number of samples taken per second, in hertz (Hz). CD quality is 44,100 Hz.The digital sound is closer to the original, so better quality, but a larger file
Bit depth (sample resolution)The number of bits used to store each sampleEach sample is measured more accurately, so better quality, but a larger file
DurationHow many seconds of sound are recordedLarger file; no change to quality
Pixel
A single dot of colour: the smallest element of a bitmap image.
Colour depth
The number of bits used to represent the colour of each pixel.
Resolution
The number of pixels in an image, often given as width × height.
Metadata
Data about data, e.g. an image's width, height and colour depth stored in the file.
Sample rate
The number of samples of a sound wave taken each second, measured in hertz.
Bit depth
The number of bits used to store each sound sample (also called sample resolution).

1.2.5 Compression

Compression reduces the size of a file. It is needed so that files take up less storage space, are quicker to upload, download and stream, use less bandwidth, and can be sent where there are size limits (e.g. email attachments).

LossyLossless
HowPermanently removes data, e.g. detail the human eye or ear is unlikely to noticeFinds patterns and stores the data more efficiently; no data is lost
Original restored?No: the original file can't be recreatedYes: the original can be rebuilt exactly
File sizeMuch smallerNot reduced as much
Use forPhotos, music, video streaming where a small loss of quality is acceptableText documents, program files, spreadsheets, where losing any data would break the file
ExamplesJPEG, MP3, MP4PNG, ZIP, FLAC, GIF

One lossless method: run-length encoding

Run-length encoding stores a run of repeated values once, with a count. It isn't named in the spec, but it shows how lossless compression can make a file smaller without losing anything.

def rle(text):
    result = ""
    count = 1
    for i in range(1, len(text) + 1):
        if i < len(text) and text[i] == text[i - 1]:
            count = count + 1
        else:
            result = result + str(count) + text[i - 1]
            count = 1
    return result

row = "WWWWWWBBBWWWW"
print(row, "->", rle(row))
print(len(row), "characters ->", len(rle(row)), "characters")

WWWWWWBBBWWWW -> 6W3B4W
13 characters -> 6 characters

★ EXAM TIP: JUSTIFY LOSSY OR LOSSLESS

A program or text file must use lossless: losing even one bit could stop the program running or change the meaning of the text. A photo on a website can use lossy: a slight loss in quality won't be noticed, and the smaller file loads faster.

Compression
Reducing the size of a file so it takes less storage space and transmits faster.
Lossy compression
Compression that permanently removes some data, so the original file can't be restored exactly.
Lossless compression
Compression that reduces file size without losing any data, so the original can be restored exactly.

Knowledge organiser

RAM vs ROM

  • RAM: volatile, read/write, programs in use
  • ROM: non-volatile, read only, boot instructions
  • Virtual memory: secondary storage used as RAM when full; slow

SECONDARY STORAGE

  • Magnetic: HDD/tape, cheap, high capacity, moving parts
  • Solid state: SSD/flash, fast, durable, dearer
  • Optical: CD/DVD/Blu-ray, cheap, low capacity
  • Compare: capacity, speed, portability, durability, reliability, cost

UNITS

  • Bit → nibble (4) → byte (8)
  • KB → MB → GB → TB → PB (× 1000)
  • bits ÷ 8 = bytes

FILE SIZES (BITS)

  • Image = colour depth × height × width
  • Sound = sample rate × bit depth × seconds
  • Text = bits per char × no. of chars

NUMBERS

  • 8-bit binary: 0–255; columns 128 … 1
  • Hex: 0–F; 2 digits = 1 byte; nibble each
  • Overflow: result needs more bits than available
  • Left shift × 2ⁿ, right shift ÷ 2ⁿ

CHARACTERS

  • Character set: unique binary code per character
  • ASCII: 7 bits, 128 chars; 'A' = 65
  • Unicode: 16/32 bits, all languages, emoji
  • n bits → 2ⁿ characters

IMAGES AND SOUND

  • Pixels; colour depth; resolution; metadata
  • Sampling: sample rate (Hz), bit depth, duration
  • Higher = better quality, bigger file

COMPRESSION

  • Smaller files: less space, faster transfer
  • Lossy: data removed for good (JPEG, MP3)
  • Lossless: restored exactly (PNG, ZIP)

Give two differences between RAM and ROM.

Kai's computer runs slowly when he has many programs open. Explain how virtual memory is used, and why it makes his computer slow.

  • When RAM is full (1), part of secondary storage is used as extra RAM (1).
  • Data/programs not currently in use are moved from RAM to virtual memory, and swapped back when needed (1).
  • Secondary storage is much slower to access than RAM, so swapping takes time (1).

A delivery company gives its drivers tablets. Explain why solid state storage is more suitable than magnetic storage for the tablets. Give two reasons.

  • Faster access (1) so delivery information loads quickly at each stop (1). Accept: lower power use → longer battery life.
