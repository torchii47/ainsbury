1Linear search

  • Works on unsorted lists
  • Best case: 1 comparison
  • Worst case: every item

How it works

  1. Start at the first item.
  2. Compare it with the target.
  3. If it matches, stop and return the position.
  4. Otherwise move to the next item.
  5. If you reach the end without a match, the item isn't there: return -1.

2Binary search

            
    
                
  • List must be sorted
    • 
                
  • Halves what's left each time
    • 
                
  • 1,000 items: at most 10 comparisons
    • 
            

            

                

                    
How it works

                    
    
                        
  1. Set low to the first index and high to the last.
    2. 
                        
  2. Find the middle: mid = (low + high) // 2.
    3. 
                        
  3. If items[mid] is the target, stop.
    4. 
                        
  4. If the target is smaller, discard mid and everything above it: high = mid - 1.
    5. 
                        
  5. If it's larger, discard mid and everything below it: low = mid + 1.
    6. 
                        
  6. Repeat until it's found, or low passes high (not there: return -1).
    7.

3Bubble sort

            
    
                
  • Swaps neighbouring pairs
    • 
                
  • Stops after a pass with no swaps
    • 
                
  • Sorts in place
    • 
            

            

                

                    
How it works

                    
    
                        
  1. Compare the first two items. If they're in the wrong order, swap them.
    2. 
                        
  2. Move along one place and compare the next pair. Carry on to the end: that's one pass.
    3. 
                        
  3. After each pass the largest unsorted item has bubbled to its place at the end.
    4. 
                        
  4. Repeat passes until a whole pass makes no swaps.
    5.

4Insertion sort

            
    
                
  • Sorted part grows from the left
    • 
                
  • Good for small or nearly sorted lists
    • 
                
  • Sorts in place
    • 
            

            

                

                    
How it works

                    
    
                        
  1. Treat the first item as a sorted list of one.
    2. 
                        
  2. Take the next item.
    3. 
                        
  3. Move each bigger item in the sorted part one place right, until you find the gap where it belongs.
    4. 
                        
  4. Insert it. Repeat until every item has been inserted.
    5.

5Merge sort

            
    
                
  • Divide, then merge
    • 
                
  • Fast on large lists
    • 
                
  • Needs extra memory
    • 
            

            

                

                    
How it works

                    
    
                        
  1. Split the list in half, then split each half again, until every list has one item. A list of one is already sorted.
    2. 
                        
  2. Merge pairs of lists: compare the front item of each and take the smaller one each time.
    3. 
                        
  3. Keep merging until there's one sorted list.
    4.

Comparing the algorithms

            
Judge an algorithm by its execution time, the number of comparisons it makes, and the memory it needs. For a list of n items:

            

                

                    
AlgorithmBest caseWorst caseMemoryUse it when...

                    
Linear searchTarget is first: 1 comparisonLast or missing: n comparisonsNo extraThe list is short, unsorted, or searched only once

                    
Binary searchTarget is in the middle: 1 comparisonAbout 10 for 1,000 items, 20 for 1,000,000No extraThe list is sorted and searched often

                    
Bubble sortAlready sorted: one pass, no swapsReverse order: swaps on every comparisonIn placeThe list is small, or you need the simplest code

                    
Insertion sortAlready sorted: n − 1 comparisonsReverse order: every item moves to the frontIn placeThe list is small, nearly sorted, or items arrive one at a time

                    
Merge sortAlways splits and merges everythingMuch faster than bubble or insertion on big listsNeeds extra memory for the sub-listsThe list is large and there's memory to spare

                

            

            
Exam tips

            
    
                
  • Link your choice to the scenario: how big the data is, whether it's already sorted, how often it's searched, and how much memory there is.
    • 
                
  • Binary search needs sorted data. If the list isn't sorted and is only searched once, sorting it first wastes time: use linear search.
    • 
                
  • When tracing, write down the list after every pass, insertion or merge. Method marks are available.
